# Contributing

This is a group effort. If you sat an OA, or have a write-up or photos of one, add it so the next person can practise on it. Using an LLM to turn your notes into a question and tests is fine. The checks below catch most of what LLMs get wrong.

## Add a question from the app (easiest)

1. Start the app and open **add a question** on the home page (or `http://127.0.0.1:8765/contribute`).
2. **Copy the prompt** into ChatGPT, Claude, Gemini or any LLM, and give it your notes for one question.
3. **Paste its JSON**, pick the company (or **+ new company**), and press **run checks**.
4. Fix whatever fails. Usually you ask the LLM to fix the failing tests and paste the JSON again. Then press **save to my bank** and try the question in the app.
5. Press **open pull request**. This needs the [GitHub CLI](https://cli.github.com), signed in once with `gh auth login`. The app commits just that question on top of the latest `main`, pushes it to your fork (created if needed) and opens the pull request. Your local files stay as they are.

Adding to a company you haven't downloaded? Download it on the home page first, so the duplicate check sees its questions.

## The checks

The app, `tools/add_question.py` and the pull-request check on GitHub all run the same checks:

| Check | What it means |
|---|---|
| Format | the required fields are there; the `id` is free; tests are `{in, out}` strings |
| Function spec | `spec` generates the LeetCode-style stub and the hidden input/output driver for Python, C++, Java and JavaScript |
| Python / C++ reference | `ref` (and `refcpp` if given) pass every sample and hidden test |
| Drivers in 4 languages | all four drivers read every test input identically, and the untouched stubs compile and run |
| Tests catch wrong answers | hidden tests don't all have the same answer, and every solution in `wrong` (brute force, off-by-one…) fails at least one test |
| Not already in the bank | no near-identical statement or identical sample. If it's the same question asked again, add `"alsoSeen": ["company/id"]` to the new one. If it only looks alike, add `"distinctFrom": ["company/id"]`. |

`data/catalog.json` is the company list on the home page. The app updates it in your pull request; by hand, run `python3 tools/build_catalog.py` and commit it with your question. The check fails if it's out of date.

## Add a question by hand

1. Fork the repo and clone it (a slim clone is enough; see the README). For a new company, run `git sparse-checkout add data/<key>` before creating its folder so git tracks it.
2. Write the question JSON. The format is in [`web/static/llm-prompt.md`](web/static/llm-prompt.md), which is the same prompt the app gives your LLM.
3. Check and save it:
   ```
   python3 tools/add_question.py <company> question.json                 # run the checks
   python3 tools/add_question.py <company> question.json --save          # then write data/<company>/questions/<id>.json
   python3 tools/add_question.py <company> question.json --save --name "Google"   # a new company also gets its company.json
   python3 tools/build_catalog.py                                        # (--save does this too) commit data/catalog.json
   ```
   To change a question that's already in the bank, edit its file (not `stub`/`driver`; they're generated from `spec`) and run `python3 tools/add_question.py <company> data/<company>/questions/<id>.json --save --replace`.
4. Also transcribe the source into `sources/<company>/` as Markdown, or JSON for structured parts. Keep original PDFs and photos in `raw-sources/` (git-ignored) and never commit them.
5. Open a pull request. Say where the question comes from (company, role, college, date) and what you assumed where the source was incomplete.

SQL, debugging and situational-judgement questions don't have the automatic checks yet. Add them by hand and say so in the pull request. Amazon's debugging and SJT sections are generated by `tools/amazon/`.

Older questions keep their function specs in `tools/style/specs.py`. New ones carry `spec` in their own JSON.

## Rules

- Paraphrase statements in your own words. Don't paste the test platform's text wholesale.
- No personal data: no names, emails or roll numbers of candidates. Demo credentials shown inside a test are fine.
- If a statement is too incomplete to grade, add it to `offlist` in `company.json` with a short reason instead of guessing.
- Changes outside `data/` and `sources/` (the app, tools, setup scripts) need a review from the maintainer (`.github/CODEOWNERS`). Open an issue first for big changes.
- Keep the server dependency-free (Python standard library only) and the frontend build-free.
